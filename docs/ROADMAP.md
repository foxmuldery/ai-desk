# 研发路线与里程碑

## 原则

先实现可验收的单机闭环，再扩展多电脑和多应用。每阶段结束必须记录测试证据、已知限制和下一阶段入口。未测试功能标记为 planned，不写成 complete。

## M0 — 设计与环境盘点

- [ ] 记录 Mac Studio 的 macOS 版本、处理器、运行用户与现有环境。
- [ ] 确认 Codex CLI/SDK 的实际安装方式与可用执行模式。
- [ ] 确认手机 Android 版本、浏览器与 Typeless 设置。
- [ ] 确认手机与 Mac Studio 是否在同一可信 LAN。
- [ ] 选择可随时重建的非生产测试目录。
- [ ] 确定服务端口、认证方式和日志目录。
- [ ] 写出最小威胁模型与回滚方式。

完成标准：环境记录存在；没有改路由器固件；没有公网暴露服务。

## M1 — 单机 MVP

- [ ] 手机响应式页面：输入、提交、任务列表、详情。
- [ ] Typeless 通过标准文本输入框提供语音转文字。
- [ ] 任务创建、SQLite 持久化、幂等请求。
- [ ] Mac Studio 本机 Agent。
- [ ] 第一个受控适配器：Codex 或安全的 dry-run adapter。
- [ ] 任务状态、事件记录、结果摘要。
- [ ] 手机端完成/失败/需决策通知。
- [ ] 中文 TTS 播报任务摘要。
- [ ] 认证、目录白名单、危险操作拦截。

完成标准：在测试目录提交一条任务，可追踪从创建到终态；服务重启后任务记录仍在；错误任务不会被报告为成功。

## M2 — 稳定性与恢复

- [ ] 服务开机自启配置及卸载说明。
- [ ] 日志轮转、健康检查和可诊断错误。
- [ ] 重复提交与客户端重试测试。
- [ ] 任务取消语义与取消失败说明。
- [ ] Agent 断线/重连。
- [ ] 对运行中任务做 reconciliation，而不是盲目重跑。
- [ ] Android 锁屏、省电、浏览器退出测试。
- [ ] SQLite 备份与恢复测试。

## M3 — 多电脑执行代理

- [ ] 设备注册、唯一 ID、名称与 capabilities。
- [ ] Agent 主动建立认证连接。
- [ ] 心跳、在线状态、版本和最近活动。
- [ ] 指定目标电脑执行。
- [ ] 任务排队、节点忙碌策略与并发限制。
- [ ] 断线时任务状态准确。
- [ ] 各节点可配置不同的允许目录与适配器。

完成标准：至少两台 Mac 可独立接收任务；手机可选择目标设备；离线设备不会被当作已执行；断线不会产生伪成功。

## M4 — 应用适配器框架

优先顺序：
1. Codex / 受控命令行任务
2. Git 与测试脚本
3. 文件检查和批处理
4. 浏览器自动化（仅在用户授权的站点与会话内）
5. Blender / 图像 / 音视频处理
6. 其他有 API、脚本或 UI 自动化接口的应用

每个适配器必须包含参数 schema、权限声明、超时与取消策略、输出脱敏、成功验收规则、测试与操作记录。

## M5 — Android 体验升级

- [ ] 评估 PWA 是否足够。
- [ ] 若通知或后台行为不足，开发 Android 原生外壳。
- [ ] 应用图标、专用启动页、深色 AI 总机视觉。
- [ ] 通知分类、振动、中文 TTS。
- [ ] 任务历史、快捷目标电脑和快速重试。
- [ ] 离线时明确显示未提交/未送达，禁止假装已接收。

## M6 — 长期运行与跨网络访问（可选）

- [ ] 开机启动与服务恢复。
- [ ] 监控与健康报告。
- [ ] 外网访问方案单独威胁建模；优先 VPN，不将 API 直接暴露公网。
- [ ] 用户明确授权后再实现跨网络访问。

## 暂不纳入路线

- 修改 Linksys MX5300 固件。
- 购买 ATA、IP 电话机或录音盒。
- 自动执行任意终端命令。
- 无人审核的删除、部署、发布或支付操作。
- 未验证的后台常驻或免唤醒语音。
