# Android 客户端：S22 Ultra + Typeless

## 产品目标

把闲置 Samsung Galaxy S22 Ultra 变成专用 AI 总机。第一版优先采用响应式 Web/PWA，避免立即投入原生 App 开发；如果真实设备测试证明通知、锁屏或后台能力不足，再评估原生 Android 客户端。

## 已知设备与约束

- 设备：Samsung Galaxy S22 Ultra；Android 版本待现场确认。
- 已安装 Typeless。
- Typeless 被视为系统键盘/语音转文字输入方式，不假设有公开 API。
- Linksys MX5300 保持原厂固件。
- 默认手机和 Mac Studio 在同一可信局域网。
- 首版不做免触摸唤醒、持续监听或真实电话线路。

## 主要页面

### 1. 总机首页
- 连接状态：在线 / 断开 / 连接中。
- 大型“交代任务”输入区。
- 默认目标电脑与下拉选择。
- 最近任务：执行中、待审批、已完成、失败。
- 快捷动作：查看状态、查看报告、重试（后端需先检查幂等性）。

### 2. 任务输入
1. 用户点击文本输入框。
2. 切换到 Typeless 键盘并口述。
3. 文字出现在输入框。
4. 用户确认任务、目标设备、适配器和允许目录。
5. 提交后等待服务端明确的 accepted 响应。
6. 请求失败时显示“未提交”，保留文字并允许安全重试。

首版不能把 Typeless 当作自动启动语音的程序接口。不要依赖模拟点击、滥用无障碍权限或后台录音。

### 3. 任务详情
- 任务名称、目标设备、适配器。
- 状态、创建时间、最近更新。
- 事件时间线。
- 执行结果摘要和错误信息。
- 验收证据、报告链接。
- 取消/审批操作（只在后端支持时显示）。

### 4. 通知和语音播报
通知类型：任务成功、任务失败、需要用户决策、目标设备离线或任务状态无法确认。

首版在页面打开时可以使用浏览器语音合成。后台/锁屏通知能力必须在 S22 Ultra 上实测；不能假设 PWA 在所有省电设置下都能可靠运行。若后台通知不稳定，后续开发原生 Android 客户端，使用系统通知、通知频道、振动和 Android TTS。

## 视觉方向

- 深色界面，红色作为主要交互色，参考经典电话的实体按钮感。
- 首页最重要的元素是“交代任务”。
- 录音和输入状态清楚；Typeless 完成转写后先展示文字，不自动执行未确认的危险指令。
- 任务状态使用文字和图标双重表达，不能只依赖颜色。
- 适配 S22 Ultra 竖屏和单手操作。
- 无需复制 Typeless 的视觉设计；AI Desk 负责任务工作流。

## 失败与恢复状态

- 未连接：展示 Coordinator 地址与连接检查结果。
- 未提交：保留输入文字，允许重试。
- 任务排队：显示已接收，不显示“执行中”。
- 设备离线：阻止立即派发，允许排队或改选设备。
- 状态未知：说明正在核对执行端，不把它标为成功。
- 手机重新打开：从服务端重新加载任务，而非依赖本地内存。

## 验收

- 在 S22 Ultra 上可通过 Typeless 填入中文指令。
- 能选择目标电脑并提交。
- 服务端未确认接收时 UI 不显示已提交。
- 锁屏、切换应用、浏览器退出和省电设置下的行为有测试记录。
- 任务成功/失败/需决策状态显示正确。
